class PilotDataset(Dataset):
    def __init__(self, pairs, processor, max_target_length):
        self.pairs = pairs
        self.processor = processor
        self.max_target_length = max_target_length

    def __len__(self):
        return len(self.pairs)

    def __getitem__(self, idx):
        page_id, img_path, gt_path = self.pairs[idx]

        image = Image.open(img_path).convert("RGB")
        pixel_values = self.processor(image, return_tensors="pt").pixel_values.squeeze(0)

        with open(gt_path, "r", encoding="utf-8") as f:
            target_text = f.read().strip()

        labels = self.processor.tokenizer(
            target_text,
            add_special_tokens=True,
            max_length=self.max_target_length,
            truncation=True,
            padding="max_length",
            return_tensors="pt",
        ).input_ids.squeeze(0)

        # Ignore padding in the loss
        labels[labels == self.processor.tokenizer.pad_token_id] = -100

        return {"pixel_values": pixel_values, "labels": labels, "page_id": page_id}

Here are four optimizations to fix this issue, ordered by effectiveness:

Key Optimizations
- Enable Mixed Precision (FP16 / BF16) — reduces memory usage by nearly half without
  modifying batch size or resolution.
- Enable Gradient Checkpointing — trades a slight decrease in training speed for massive

- Resize Processor Image Inputs — if your images are extra high-resolution (e.g.,

Why LoRA Works Extremely Well Here
- Domain Adaptation vs. Representation Rewriting: Donut's underlying Swin-Encoder and
  MBart/Transformer-Decoder already know how to process visual document structures and
  syntax. Your goal is domain adaptation (learning Shakespearean English layout, 16th-century
  typeface quirks, and specific column reading order). LoRA is ideally suited for domain
  alignment without destroying the base model's pre-trained weights.
- Mitigates Overfitting on Small/Medium Datasets: With ~926 full-page training examples,
  updating all ~200M+ parameters in full precision carries a strong risk of overfitting —
  especially over 10–12 epochs. By restricting updates to low-rank matrices (updating under
  2% of parameters), LoRA acts as an implicit regularizer, preventing the decoder from
  memorizing repetitive formatting artifacts.
- Massive VRAM Savings (Solves your OOM): Full Fine-Tuning needs ~14.2 GB VRAM allocation
  (causing your OutOfMemoryError). LoRA (r=16, alpha=32) cuts active trainable parameters
  down to <1–2%, reducing overall optimizer/gradient memory consumption by 60–70%. You can
  safely run batch sizes of 1 or 2 on a 16GB T4 GPU without lowering image resolution.

Python Script (With Multithreading & Checkpointing) — processes images in parallel using
threads to finish in minutes rather than hours; automatically skips images that already
have a .txt file generated, so it can be safely paused and resumed:

import os
import glob
from concurrent.futures import ThreadPoolExecutor, as_completed
from google.cloud import vision

# Set paths
IMAGE_DIR = "./output_pages"     # Folder containing your page images (.png / .jpg)
OUTPUT_DIR = "./extracted_gt"    # Folder where .txt files will be saved
MAX_WORKERS = 10                 # Parallel threads to speed up API calls

os.makedirs(OUTPUT_DIR, exist_ok=True)
client = vision.ImageAnnotatorClient()

def process_page(image_path):
    filename = os.path.basename(image_path)
    base_name, _ = os.path.splitext(filename)
    txt_path = os.path.join(OUTPUT_DIR, f"{base_name}.txt")

    # Skip if text file already exists (allows resuming if interrupted)
    if os.path.exists(txt_path):
        return f"Skipped (already exists): {base_name}.txt"

    try:
        with open(image_path, "rb") as image_file:
            content = image_file.read()

        image = vision.Image(content=content)

        # document_text_detection is optimized for dense book/document pages
        response = client.document_text_detection(image=image)

        if response.error.message:
            return f"API Error on {filename}: {response.error.message}"

        extracted_text = response.full_text_annotation.text if response.full_text_annotation else ""

        # Save to .txt file
        with open(txt_path, "w", encoding="utf-8") as f:
            f.write(extracted_text)

        return f"Done: {filename} -> {base_name}.txt"

    except Exception as e:
        return f"Failed processing {filename}: {str(e)}"

def main():
    # Find all PNG/JPG images
    image_paths = sorted(glob.glob(os.path.join(IMAGE_DIR, "*.png")))
    if not image_paths:
        image_paths = sorted(glob.glob(os.path.join(IMAGE_DIR, "*.jpg")))

    print(f"Found {len(image_paths)} images to process.")

    # Process images concurrently
    with ThreadPoolExecutor(max_workers=MAX_WORKERS) as executor:
        futures = [executor.submit(process_page, path) for path in image_paths]
        for future in as_completed(futures):
            print(future.result())

if __name__ == "__main__":
    main()

import os
import glob
import time
import json
from pathlib import Path
from PIL import Image
from google import genai
from google.genai import types
from kaggle_secrets import UserSecretsClient

# ---------------------------------------------------------------------------
# CONFIGURATION
# ---------------------------------------------------------------------------
MODEL_NAME = "gemini-1.5-flash"  # Fast, highly accurate for OCR tasks
IMAGE_DIR = Path("/kaggle/input/complete-works-of-shakespeare/output_pages")
OUTPUT_DIR = Path("/kaggle/working/gemini_ocr_output")
PROGRESS_LOG = Path("/kaggle/working/gemini_progress.json")

# Free tier rate limit delay (15 Requests Per Minute = 1 call every ~4 seconds)
REQUEST_DELAY_SECONDS = 4.0

OUTPUT_DIR.mkdir(parents=True, exist_ok=True)

# ---------------------------------------------------------------------------
# INITIALIZE GEMINI CLIENT
# ---------------------------------------------------------------------------
user_secrets = UserSecretsClient()
api_key = user_secrets.get_secret("GEMINI_API_KEY")
client = genai.Client(api_key=api_key)

# System prompt forcing verbatim transcription and column ordering
OCR_PROMPT = (
    "You are an expert OCR engine. Transcribe all text from this document image verbatim.\n"
    "Rules:\n"
    "1. Do not correct archaic spelling, punctuation, or formatting.\n"
    "2. Do not include markdown conversational intro/outro text (e.g., 'Here is the text').\n"
    "3. If the page contains two text columns, read the ENTIRE left column top-to-bottom first, "
    "then read the ENTIRE right column top-to-bottom.\n"
    "4. Output ONLY the raw extracted page text."
)

# ---------------------------------------------------------------------------
# PROGRESS LOGGING & UTILS
# ---------------------------------------------------------------------------
def load_progress() -> set:
    if PROGRESS_LOG.exists():
        return set(json.loads(PROGRESS_LOG.read_text(encoding="utf-8")))
    return set()

def save_progress(done_set: set):
    PROGRESS_LOG.write_text(json.dumps(sorted(done_set)), encoding="utf-8")

# ---------------------------------------------------------------------------
# MAIN OCR PROCESSING LOOP
# ---------------------------------------------------------------------------
def run_ocr():
    done = load_progress()
    image_paths = sorted(list(IMAGE_DIR.glob("*.png")))

    print(f"Total images found: {len(image_paths)}")
    print(f"Already processed in prior runs: {len(done)}")

    for idx, img_path in enumerate(image_paths, 1):
        if img_path.name in done or img_path.name == "bio_blank.png":
            continue

        out_path = OUTPUT_DIR / f"{img_path.stem}.txt"

        try:
            image = Image.open(img_path)

            # Send multimodal request
            response = client.models.generate_content(
                model=MODEL_NAME,
                contents=[OCR_PROMPT, image],
                config=types.GenerateContentConfig(
                    temperature=0.0  # Zero temperature ensures deterministic transcription
                )
            )

            extracted_text = response.text.strip() if response.text else ""
            out_path.write_text(extracted_text, encoding="utf-8")

            done.add(img_path.name)
            save_progress(done)
            print(f"[{idx}/{len(image_paths)}] Processed: {img_path.name}")

            # Pace requests to comply with AI Studio Free Tier RPM
            time.sleep(REQUEST_DELAY_SECONDS)

        except Exception as e:
            err_msg = str(e)
            print(f"FAILED {img_path.name}: {err_msg}")

            # If rate limit (429) hit, pause and retry
            if "RESOURCE_EXHAUSTED" in err_msg or "429" in err_msg:
                print("Quota limit reached. Sleeping 60 seconds before continuing...")
                time.sleep(60)

if __name__ == "__main__":
    run_ocr()

[AI]
No, hitting the RPM (Requests Per Minute) limit will not stop your API usage for the rest
of the day. RPM limits operate on a 60-second sliding window. If too many requests are sent
within a single minute, the Gemini API temporarily throws an HTTP 429 RESOURCE_EXHAUSTED
error; waiting 30 to 60 seconds for the window to slide forward restores the per-minute
allowance and calls can resume immediately.

How Rate Limit Reset Windows Work
- Requests Per Minute (RPM): resets continuously on a 60-second rolling window — hitting
  this just needs a brief pause (e.g. time.sleep(4) or exponential backoff) before retrying.
- Tokens Per Minute (TPM): resets continuously on a 60-second rolling window.
- Requests Per Day (RPD): this is the only limit that stops usage for the rest of the day —
  once exhausted, you must wait until it resets at midnight Pacific Time (PST/PDT).

If 429 errors occur in a script, catch the exception, sleep for 10–60 seconds, and retry
the failed image — no remaining daily requests are lost.

In machine learning and AI, OOD stands for Out-Of-Distribution.

Core Concept
- In-Distribution (ID): Data that matches the style, structure, formatting, or domain of
  the dataset used to train the model.
- Out-Of-Distribution (OOD): Data that comes from a distinctly different layout, format,
  noise level, or domain than what the model was trained on.

What It Means in Your Context (E34)
In your codebase's evaluation setup (eval/robustness.py):
- The OOD Data: refers to the held-out test pages with noticeably different structures —
  such as the Sonnets or complex multi-column layouts — that the model hasn't learned to
  expect.
- The Target (OOD F1 drop ≤ 10%): this is a stress-test threshold. It demands that when
  the model is given these weird, unfamiliar layouts, its overall accuracy (F1 score)
  shouldn't degrade by more than 10 percentage points relative to its performance on
  standard, familiar pages.

In short: OOD measures how gracefully the model handles real-world curveballs it wasn't
explicitly trained on.

REFLECTION
==============================================================================

After A1, I expected fine-tuning an OCR model to be fairly straightforward. That
assumption broke almost immediately: Tesseract isn't something you can fine-tune through
PyTorch at all, so it was out as a fine-tuning target from the start. We also had an
existing ground truth from the original Internet Archive scan the PDF came from, but it
was too buggy to trust, so we discarded it and built our own instead — using the Gemini
API (3.5 Flash Lite) to extract pages in batches.

We then tried Donut, but fine-tuning it needed more GPU/session time than our Kaggle
free-tier accounts could give us. My teammate separately tried fine-tuning PaddleOCR; its
results were already poor, and fine-tuning made them worse, not better. Since our NFR was
robustness, and none of the fine-tuning routes could meet it under our resource
constraints, we settled on a zero-shot VLM pipeline for page extraction instead.

For chunking, we used a regex-based strategy for the two-column play pages and a semantic
(embedding-similarity) strategy for the biographical pages. I planned the approach; my
teammate implemented it. Embedding and indexing used the BGE-M3 model, which we'd already
used and trusted from a previous project, with a FAISS flat index for fast search.

Once the pipeline was built, we spent Friday and Saturday filling in the form, repo, and
transcripts. The form itself was completed with AI assistance, but grounded in our actual
notebooks, scripts, and outputs rather than invented numbers.
